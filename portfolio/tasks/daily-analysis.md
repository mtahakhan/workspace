# portfolio-daily-analysis task instructions

Generate today's portfolio analysis report. This runs after the `portfolio-price-fetch` task, which has already appended today's price to each ticker's `price_history/{TICKER}.jsonl` (there is no separate prices.json snapshot - each file's last line is the current price).

Working directory: `/Users/user/openclaw/workspace/portfolio`

Steps:
1. Run `python3 analyze_portfolio.py` (stdout is clean JSON, all diagnostics go to stderr - don't mix them). This is the deterministic numeric layer: it computes position/portfolio value, cost basis, gain/loss, sector concentration, largest positions, high-water-mark/drawdown (from full price history), daily movers, trend (since-inception/30d/90d/365d), annualized_returns (a real XIRR from transaction_lots.csv's actual purchase lots via compute_lots.py, not an estimate), and stale_prices (tickers whose latest price is 2+ days old). Do NOT recompute any of these numbers yourself by reasoning over the raw data - use exactly what this script outputs. If you think a number looks wrong, that's a bug to fix in analyze_portfolio.py, not something to override by hand.
2. Read the `caveats` array in the script's output and respect them - in particular: use `annualized_returns.portfolio_xirr_pct` (not gain_pct) as the figure to check against the 10-15%/yr target, don't over-interpret any single position's XIRR without checking its `weighted_avg_holding_days` first (short holding periods produce mathematically extreme annualized numbers - that's correct math, not noteworthy on its own), and flag anything in `stale_prices` in the report.
3. If `annualized_returns.tickers_without_lot_data` is non-empty, or if you know new trades happened since `transaction_lots.csv` was last generated, re-run `python3 compute_lots.py` first (it rebuilds transaction_lots.csv from transactions.csv via FIFO) - but only if `transactions.csv` has actually been updated with new rows; it won't discover new trades on its own.
4. Identify notable movers from the script's `movers` output and do targeted WebSearch ONLY on those - never do a serial web search across all positions, that timed out a prior version of this pipeline (600s timeout doing per-ticker research on everything). Keep it lean.
5. Write a markdown report to `daily-analysis/YYYY-MM-DD.md` (today's date) with sections: Executive Summary, Portfolio Overview (value/cost/gain/XIRR/position count), Sector Breakdown, Largest Positions, Movers Analysis. Match the style of existing reports in that directory, but now cite the real XIRR instead of a non-annualized total return.
6. Only include prescriptive action recommendations when something genuinely warrants it - not every day.
7. Send a push notification only if there's something genuinely notable (large move, target breached, stale prices, etc.) - not a routine "report ready" ping every day.

This is intended to be extended with additional research dimensions later - keep the report structure additive (new sections can be appended) rather than assuming this is the final scope. If you add a new computed indicator, add it to analyze_portfolio.py so it stays deterministic rather than computing it ad hoc in this file.
